# Compact Node Types Schema Reference (`compact-node-types.yaml`)

This document defines the structure, typing syntax, and validation invariants for `compact-node-types.yaml`, generated by [`CompactNodeTypes`](file:///home/michael/projects/go/tree-sitter/internal/tree-sitter/build/compact.go#L65) and audited by [`ValidateCapture`](file:///home/michael/projects/go/tree-sitter/internal/tree-sitter/build/compact.go#L292).

---

## 1. Overview & Purpose

The compact node types format is a token-efficient, lossless YAML representation of Tree-sitter's AST grammar schema. It translates Tree-sitter's verbose `node-types.json` into a concise dictionary designed for:
1. **LLM Context Optimization**: Reducing AST schema prompt token consumption by 60% to 80%.
2. **Static Analysis & Tooling**: Providing unambiguous parent-child-field schemas for code analysis and AST transformations.
3. **Lossless Verification**: Guaranteeing 100% bidirectional correspondence with `node-types.json`.

---

## 2. Document Layout

A valid `compact-node-types.yaml` document consists of two root-level mappings: `supertypes:` and `nodes:`.

```yaml
# Compact Tree-sitter Node Types (Generated from node-types.json)
# Legend:
#   field_name? : optional field
#   [Type]      : multiple occurrences allowed
#   TypeA | B   : alternative node types

supertypes:
  <supertype_name>: [<subtype_name_1>, <subtype_name_2>]

nodes:
  <node_type_name>:
    fields:
      <field_name>: <type_expression>
      <optional_field_name>?: <type_expression>
    children: <type_expression>
```

---

## 3. Section Specifications

### 3.1. `supertypes` Mapping

Defines Tree-sitter abstract node categories (such as `_expression`, `_statement`, `_type`) and their concrete subtypes using token-efficient flow sequence notation (`[...]`).

- **Key**: String identifier of the supertype (often prefixed with `_`).
- **Value**: Alphabetically sorted bracketed flow sequence of named node type identifiers.

#### Example
```yaml
supertypes:
  _declaration: [class_declaration, function_declaration, variable_declaration]
  _expression: [binary_expression, call_expression, identifier, number_literal, string_literal]
```

### 3.2. `nodes` Mapping

Defines every named, concrete AST node produced by the parser.

- **Key**: String identifier matching the named node's `type` attribute in `node-types.json`.
- **Value**: Object containing optional `fields:` and `children:` attributes.

| Attribute | Type | Description |
| :--- | :--- | :--- |
| `fields` | mapping | Named fields accessible on the AST node. |
| `children` | string (type expression) | Permitted unnamed children permitted within the node. |

#### Example
```yaml
nodes:
  call_expression:
    fields:
      arguments: argument_list
      function: _expression
  for_statement:
    fields:
      body: statement_block
      condition?: _expression
      initializer?: _expression
      update?: _expression
  compound_statement:
    children: [_statement]
```

## 4. Type Expression Grammar

Field values and `children` definitions use a concise type expression syntax:

| Syntax | Name | Meaning | Equivalent JSON Descriptor |
| :--- | :--- | :--- | :--- |
| `Type` | Single Type | Exactly one required node of type `Type`. | `{"required": true, "multiple": false, "types": [{"type": "Type", "named": true}]}` |
| `Type?` (in field key) | Optional Field | Field may be omitted (zero or one instance). | `{"required": false, ...}` |
| `TypeA \| TypeB` | Union Type | Any one of the alternative types listed. | `{"types": [{"type": "TypeA"}, {"type": "TypeB"}]}` |
| `[Type]` | Multiplicity (Array) | Zero or more occurrences of `Type`. | `{"multiple": true, "types": [{"type": "Type"}]}` |
| `[TypeA \| TypeB]` | Multiplicity Union | Zero or more occurrences of any listed alternative. | `{"multiple": true, "types": [{"type": "TypeA"}, {"type": "TypeB"}]}` |
| `any` | Unconstrained | Any anonymous token or unconstrained named node. | Empty or purely anonymous type sequence. |

## 5. Lossless Validation Invariants

[`ValidateCapture`](file:///home/michael/projects/go/tree-sitter/internal/tree-sitter/build/compact.go#L292) enforces strict bidirectional equivalence between `node-types.json` and `compact-node-types.yaml`:

1. **Supertype Coverage**: Every supertype declared in JSON must exist in YAML with identical, sorted subtype sequences. No extra or omitted supertypes are permitted.
2. **Node Completeness**: Every named entry in `node-types.json` must be present under `nodes:` (unless it is purely a supertype definition).
3. **Field Parity**:
   - Every field in JSON must exist under the node's `fields:` block in YAML.
   - Optional fields (`required: false` in JSON) must end with `?` in the YAML key.
   - Required fields (`required: true` in JSON) must not have `?`.
   - Multiplicity (`multiple: true`) must be enclosed in brackets `[...]`.
   - All referenced type alternatives must match sorted union components.
4. **Children Parity**:
   - A node with a `children` descriptor in JSON must declare a matching `children:` type expression in YAML.
   - A node without children in JSON must not declare a `children:` attribute in YAML.
5. **No Extraneous Types**: No node, field, or supertype may exist in YAML that is not defined in `node-types.json`.

## 6. Comparison: JSON vs. Compact YAML

### Raw `node-types.json` (51 lines, ~320 tokens)
```json
[
  {
    "type": "binary_expression",
    "named": true,
    "fields": {
      "left": {
        "multiple": false,
        "required": true,
        "types": [
          {
            "type": "_expression",
            "named": true
          }
        ]
      },
      "operator": {
        "multiple": false,
        "required": true,
        "types": [
          {
            "type": "+",
            "named": false
          },
          {
            "type": "-",
            "named": false
          }
        ]
      },
      "right": {
        "multiple": false,
        "required": true,
        "types": [
          {
            "type": "_expression",
            "named": true
          }
        ]
      }
    }
  }
]
```

### Generated `compact-node-types.yaml` (6 lines, ~28 tokens)
```yaml
nodes:
  binary_expression:
    fields:
      left: _expression
      operator: any
      right: _expression
```

**Net result:** Over 90% reduction in this node's footprint while retaining full structural semantics.
